# Reference order

Reference tables and rendered examples are keyed by name, sorted in
`schemaRows` and `stableJson`. Their order is independent of property insertion
order in the resolved specification.

Operation facts come from the build's resolved specification capability.
Standalone generation resolves the original definition through apidef. No
serialized point contracts are required or read.

`resolved-parity.test.ts` checks alphabetical property and example order,
compact model fields, and active route selection across editions.
